Factory Inventory Management System

System architecture overview — a demo full-stack application with a Vue 3 single-page frontend, a Python FastAPI backend, and in-memory mock data loaded from JSON files. No database.

Vue 3 · Composition API Vite FastAPI · Python 3.11+ Pydantic v2 In-memory JSON data

System Architecture

Three tiers in two processes: the Vite dev server serves the SPA on port 3000; the browser calls the FastAPI process on port 8001 directly via CORS-enabled REST; the API filters data held in Python memory, loaded once at startup from JSON files.

Data Flow

A single request path drives every screen. Four global filters (Time Period, Warehouse, Category, Order Status) live in a shared composable and are translated into query parameters.

User changes filterFilterBar.vue
→
Shared filter stateuseFilters composable
→
API client builds queryapi.js · ?warehouse=&month=…
→
FastAPI endpointmain.py · /api/*
→
In-memory filteringapply_filters · filter_by_month
→
Pydantic validationresponse_model
→
Reactive renderrefs → computed → template
Frontend reactivity pattern: raw API responses land in refs (allOrders, inventoryItems); everything derived — totals, chart series, KPI tiles — is a computed property, so a filter change re-fetches once and the UI recalculates automatically. Time filters accept months (2025-01) or quarters (Q1-2025, expanded server-side via a quarter map).

All endpoints are read-only GETs served from memory. Filters are optional query parameters; the value all (or omission) skips a filter.

Design Notes & Constraints

Stateless, ephemeral data All data is loaded into Python lists when mock_data.py is imported. Nothing persists — restarting the server resets state to the JSON files. This keeps the demo simple but means no writes survive.
Validation as the contract Pydantic models (InventoryItem, Order, DemandForecast, BacklogItem, PurchaseOrder) are the schema. Changing a JSON data file requires updating the matching model, or responses fail validation.
Filter semantics Inventory has no time dimension, so month filters apply only to orders and dashboard summaries. Revenue goals are fixed constants: $800K per month, $9.6M YTD.
Client/server drift api.js defines methods for /api/tasks (CRUD) and POST /api/purchase-orders, but main.py implements neither — only the request model exists. These calls 404 against the current backend.
Demo-grade security CORS allows all origins, there is no authentication, and no rate limiting — intentional for local development only.
